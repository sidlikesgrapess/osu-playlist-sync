# 13 Redo F-46 (bracket noise without a word list)

Status: APPROVED by the user ("Go ahead with this but do thorough testing on it to see if its better"). Implement after item 12 commits.

## Decisions so far
- USER: a more sophisticated approach than a flat list. There must still be a fallback, and if
  the fallback scores higher, its match is the one displayed.
- USER: keep the early stop at score >= 150; the fallback query runs only when the stripped
  title found no exact match. Candidates already pooled are scored against both versions.

## Key fact
Candidates are scored only against the cleaned title (src/lib/osu.js:704,
scoreBeatmapMatch(bm, targetTitle, ...)). So "fallback wins on score" needs max over title
hypotheses inside scoring, not just an extra query. bench replays frozen queries and never
calls the cleaner; test/cleaner-diff.test.mjs is the cleaner gate. Only 5 of 37 fixtures have
tags, so a new labelled title set is needed.

## Draft design (proposed, awaiting user)
1. Parse: core + tags (any bracket type, trailing - | ~ segments, feat./ft. clauses), each
   with bracket type, position, content. The parser removes nothing.
2. Evidence per tag, no word list: shape (pp, %, stars, 1080p, fps, year, mods) = certain
   noise; repeats across the playlist (>= 2 tracks) = noise, learned, 0 API calls; echo of
   channel/artist = noise; 【】[] lean noise, 「」『』 lean title (the quoted song name);
   leading/trailing lean noise, interior leans title; structured source trailing dash
   segment = version tag; minimum letters left floor.
3. At most 2 hypotheses: H0 core (likely noise stripped), H1 core + ambiguous tags.
4. osu! arbitrates: score every candidate against H0 and H1, take max, tie goes to H0. H1
   query only when H0 had no exact match.
5. Gates: labelled title set (~60), cleaner snapshot diff listed in commit, npm run bench
   before/after, bench:cost vs 1.49/track.

## Required testing: prove it is better, not just different
- A/B harness (todo-run/f46/ab.mjs, not in bench/): run OLD cleanSongTitle (git show HEAD
  version) and NEW over the labelled title set, and report exact core-title accuracy for each,
  plus every title where they differ.
- Labelled set: at least 60 realistic titles, written before the implementation so they are not
  fitted to it. Mix YouTube uploads (Official Video, Lyrics, 【MV】, [1080p], Nightcore, osu!
  replay titles), Japanese 「」『』 quoting, songs whose real title has brackets ((feat. X),
  (Remix), (TV Size) where osu! keeps it), Spotify/Apple "- Remastered 2011", "- TV Size",
  and tags NOT in the old list (unseen noise), to test that it generalises.
- Playlist repeat signal: a test playlist where one channel's boilerplate tag recurs.
- Offline scoring A/B: max over hypotheses vs single title on the captured bench responses.
- npm run bench before and after (0 WRONG, hit >= 31), bench:cost (no rise over 1.49/track
  unless explained), cleaner snapshot diff with every change listed in the commit.
- One small live A/B on :3000 (at most 30 tagged titles, paced by searchPacer) comparing old
  and new matched beatmaps. Never bench:capture, nothing written into bench/.
- Ship only if NEW is >= OLD on every measure and strictly better on the labelled set. If it is
  not better, report the numbers to the user and do not commit the change.
