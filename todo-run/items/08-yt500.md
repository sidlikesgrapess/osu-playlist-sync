# 08 YouTube 500 + paced Search All

## Scope

**Item.** YouTube playlists stop at 100 songs. Raise the cap to 500 by following the Innertube
continuation token (one paced request per extra 100), keep `truncated` structural, and show the
popup only past 500. In the same change, pace Search All under the 60/min `/api/osu/search`
limit so a 500 song Search All does not end in "osu! is busy" rows. Overrides the F-18
"keep 100" decision (REBUILD_PLAN.md, 2026-09-24).

**Current state (scope stage).** youtube.js:89-91 never fetches continuations; the cap is 100
(youtube.js:107); the Innertube POST is a raw `fetch` with no byte cap (youtube.js:137-170);
http.js only issues GETs (http.js:50-79). parsePlaylistData reads one window and the hidden
unavailable rule compares one window's loadedCount (youtube.js:274-322). The popup copy
hardcodes 100 twice (page.js:88-96). Search All fans out at concurrency 3 with no pacing
(page.js:584, 646-651); `/api/osu/search` allows 60 per fixed 60 s window per IP
(route.js:11, rateLimit.js:58-77); a 429 marks the row rate-limited at once and only one
retry pass runs, and only when Retry-After <= 15 s (page.js:75, 598-603, 659-668).

**Decisions (no user decision needed).**
1. One exported cap constant `PLAYLIST_LOAD_CAP = 500` in youtube.js, returned as `loadCap`
   in the playlist response; the client popup reads it, so 500 is never hardcoded in page.js.
2. Continuation pacing: fixed gap (~750 ms) between Innertube requests, overall walk deadline
   (~20 s). Past the deadline, or on a failed page, stop, keep what loaded, truncated=true.
   The POST goes through a new http.js `postJson` (UA_PROFILES, timeout, byte cap).
3. Search pacer: pure `src/lib/searchPacer.js`, sliding window at 55 per 60 s, shared at
   module scope by every client call to `/api/osu/search` (Search All, paging, Refetch,
   manual search). Concurrency 3 stays.
4. 429: the pacer is penalized until now + Retry-After and the row is retried through the
   pacer, up to 3 times; only then does it end as `rate-limited`. The old "one serial retry
   after the batch if Retry-After <= 15 s" path is folded into this.
5. osu! API calls per track unchanged (this only changes when client requests are sent).

**Acceptance.**
- fetchPlaylistItems defaults to a 500 cap; extractors.js inherits it.
- A continuation token triggers one paced Innertube POST `{ context, continuation }` via the
  http.js helper; youtube.js no longer calls global fetch directly.
- Paging stops with no token or at 500 items: exactly ceil(min(N,500)/100) requests.
- Continuation pages parsed from `onResponseReceivedActions[*].appendContinuationItemsAction.continuationItems`
  through readWindowItem; positions contiguous 0..N-1.
- truncated structural: 250 walked fully -> false; 700 -> true with 500 loaded; a failed
  continuation -> true, first songs kept, no throw.
- Hidden unavailable rule across pages (100+100+46 vs '250 videos' -> 4 hidden, loaded 250);
  truncated walk infers nothing.
- HTML scrape fallback follows the same token through Innertube POST pages.
- Popup only when truncated; copy 'This playlist has 800 songs. osu!Sync loads the first 500.'
  or 'This playlist has more than 500 songs. osu!Sync loads the first 500.' from one constant,
  no dash punctuation; a 250 song playlist shows none.
- Pacer helper with node --test tests (injected clock): <= limit in any 60 s window, FIFO,
  waits rather than rejects, penalize blocks.
- 429 retried after Retry-After through the pacer; simulated 500 row run against a 60/min
  fixed window stub ends with 0 rate-limited rows.
- bench unchanged (hit 31, abstain 6, WRONG 0, offered 752); bench:cost <= 1.49.
- npm test: >= 165 tests, 0 fail, 1 todo.
- REBUILD_PLAN.md F-18 updated (cap 500, paging, truncated past 500, popup copy, pacing,
  overrides 2026-09-24); page.js:474-475, youtube.js doc comments updated.

## Implementation

### YouTube: 500 cap, continuation walk
- src/lib/youtube.js:93 `PLAYLIST_LOAD_CAP = 500`, the default `maxVideos` of `fetchPlaylistItems` (youtube.js:138) and `parsePlaylistData` (youtube.js:427). extractors.js passes no cap, so it inherits it, and forwards `loadCap` (extractors.js:327, 427).
- youtube.js:98-99 gap 750 ms between pages, walk deadline 20 s (checked before and after each gap, youtube.js:180-210).
- youtube.js:180 `followContinuations`: one POST per extra page via `postJson(INNERTUBE_BROWSE, { context, continuation: token })`; any error or unreadable page returns early and leaves the walk open ended, so the result is `truncated`, keeps the loaded songs, never throws.
- youtube.js:274 `continuationWindow` reads `onResponseReceivedActions[*].appendContinuationItemsAction.continuationItems`; youtube.js:283 `findContinuationToken` finds `continuationCommand.token` depth first.
- youtube.js:368 `addPage` numbers positions from `walk.loadedCount`, so positions are contiguous across pages; the cap counts loaded video items and sets `cut` past it.
- youtube.js:395 `finishWalk`: `truncated = cut || openEnded` (structural); the hidden unavailable rule (header length minus loaded) runs only when not truncated.
- Both attempts (Innertube and the HTML scrape) go through the same walk in `fetchPlaylistItems`, so the scrape follows the same token. youtube.js has no `fetch(` call left (grep).
- src/lib/http.js:50 `openRequest` takes `method` and `body`; http.js:143 `postJson` (JSON body, `Content-Type`, same byte cap and timeout as `fetchText`).

### Popup
- src/lib/truncationNotice.js:10 `truncationMessage({ playlistLength, loadedCount, loadCap })`; the number is the response's `loadCap`, never hardcoded. A walk cut short before the cap says "osu!Sync could only load the first N this time." page.js:488 passes `loadCap`; the old 100 copy is gone from page.js.
- src/components/TruncationDialog.js:6-16 doc comment updated.

### Search pacing
- src/lib/searchPacer.js:15 `SEARCH_RATE` 55 per 60 s sliding window, FIFO promise chain (searchPacer.js:24-69), `penalize(retryAfterSec)`; searchPacer.js:78 `pacedRequest` retries a 429 up to 3 times (`SEARCH_RETRY`, :20), and not at all when Retry-After is over 90 s.
- src/app/page.js:78 one module level pacer; page.js:82 `pacedSearch`. Every `/api/osu/search` call goes through it: `searchTargetSongs` (page.js:599-650, used by Search All, paging, Refetch and filter changes) and `handleManualSearch` (page.js:867). The old post batch retry and `RATE_LIMIT_RETRY_WAIT_CAP_S` are removed.
- page.js:165 `songListGenerationRef`, bumped in `dropSongList` (page.js:982); queued requests for a dropped list are skipped without spending a grant.
