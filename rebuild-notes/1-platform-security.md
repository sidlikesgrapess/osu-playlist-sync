# Audit: platform-security

Scope: server-side attack surface of osu!Sync — route handlers, next.config.mjs, package.json deps, and env/token handling in src/lib/osu.js:1-123. Covers open-proxy risk, injection, cost/quota abuse, secrets exposure, response/security headers, and client bundle weight (traced, not built).

Working notes (not findings, kept for reference while auditing):
- Route table already produced by Phase 0 map (rebuild-notes/00-map.md) — reused below instead of re-deriving.
- `npm audit --omit=dev` and `npm audit` gave byte-identical results: 1 critical (next@14.2.35 advisory chain) + 1 high (postcss, pulled in transitively by next). `next` is a direct runtime dependency, not dev-only, so `--omit=dev` changes nothing. `npm ls --depth=0`: jszip@3.10.1, lucide-react@1.31.0, next@14.2.35, react@18.3.1, react-dom@18.3.1 (deps); playwright@1.63.0 (devDependency only, correctly excluded by `--omit=dev` in spirit even though it wasn't the blocker here).
- Client bundle weight (traced, not built): `src/app/page.js:1` is `'use client'` and `src/app/page.js:21` does `import JSZip from 'jszip'` at module scope, no dynamic `import()` — the full JSZip implementation (used only for feature 12, "Bundle as .ZIP") ships in every visitor's initial client bundle whether or not they ever click that button. `lucide-react` is per-icon ESM tree-shaken, so its cost scales with how many icons are imported (not independently re-counted, out of file list) — marked traced.

### SEC-04 /api/download proxies full archive bytes through the Vercel function with no size, duration, or request cap — the one fallback the contract says must be capped, isn't

## Dimensions with no findings

- **memory-resource-leaks**: The osu! token cache (`src/lib/osu.js:8-9`, two module-level scalars, refreshed 60s before expiry) and the GitHub commits cache (`src/app/api/github/commits/route.js:27`, one bounded object) are both fixed-size, singleton, and correctly bounded — no unbounded growth found in any file read for this area.
- **rendering-performance**: Not applicable to this area — platform-security covers route handlers, config, and env/token plumbing, not React rendering. See the client-ui area's audit for that.
- **ui-glitch-parity**: Not applicable — none of this area's files touch `SongRow.js`/`SongCardMobile.js` or any other desktop/mobile component pair.

## Contract check (platform-security-relevant subset)

- "demo mode returns `{ isDemo: true }` without credentials and never crashes" — `getOsuAccessToken` (src/lib/osu.js:14-20) returns `null` gracefully when `OSU_CLIENT_ID`/`OSU_CLIENT_SECRET` are absent or still the placeholder value, and does not throw. Compliant within this area's scope (osu.js:1-123); how every caller handles a `null` token is outside this area's file list.
- "normal-path download bytes never pass through a Vercel function, any fallback that does is capped on the server and never reports a placeholder as real" — **violated twice**: the fallback path has no caps at all (SEC-04), and a broken mirror's HTML error page can be forwarded and reported as a real, correctly-mirrored download rather than the flagged placeholder the intentional generator produces (SEC-05).
- OAuth token is never sent to the client: confirmed by reading every route handler in this area plus `src/lib/osu.js:1-123` — `cachedToken` never appears in any `NextResponse.json(...)` payload; a live `/api/osu/search` call was inspected end-to-end and its body contains only `success/query/total/bestScore/beatmapsets/isDemo/rejection/artistConfidence`, no token or credential material.

## Summary

Counts by severity: 3 critical, 4 high, 3 medium, 3 low, plus one dependency advisory noted as high with mitigating context (SEC-08).

Top 3:
1. **SEC-01** (critical) — `music.apple.com` substring check lets `/api/playlist` be used as a blind SSRF proxy to any host, verified live against our own dev server.
2. **SEC-03 / SEC-04** (critical) — no rate limiting anywhere, and the one route that streams real file bytes through a Vercel function (`/api/download`) has no size/duration/request cap, directly contradicting the stated "capped fallback" contract.
3. **SEC-05** (high, correctness) — the mirror content-type guard is neutralized by its own `res.status === 200` clause, so a misbehaving mirror's HTML error page can be forwarded to users as a legitimate `.osz` with no placeholder flag.
