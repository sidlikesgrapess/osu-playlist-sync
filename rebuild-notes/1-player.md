# Audit: player

Traces the osu! player profile lookup path: PlayerProfile search -> /api/osu/player -> PlayerResults/PlayerSections -> /api/osu/player/beatmaps -> beatmapToSong -> songs array (selection/export/download reuse).
Work in progress, findings appended incrementally.

## Dimensions with no findings

- **memory-resource-leaks**: PlayerSections.js's audio preview (`audioRef`, lines 313-333) always pauses the previous `Audio()` before creating a new one and pauses on unmount; no listener/interval accumulation found across the files in this area.
- **network-hops-latency**: the player path correctly follows the "one window, paginate locally" convention at the HTTP level -- one call for a profile, one call per section, no per-page round trips (the problem is what happens to that one window client-side, covered by PLY-01/07/10, not extra hops).
- **security-abuse**: `parseOsuProfileRef` and the numeric-id fallback (src/lib/osu.js:88-91, src/app/api/osu/player/route.js:33) only ever build a path segment against the fixed osu.ppy.sh base inside osuApiGet; no SSRF surface. No new abuse vector beyond the generic error-message leak already covered under PLY-03.
- **artist gate / matching contracts**: the player path never runs scoreBeatmapMatch or the artist gate at all (beatmapset comes pre-matched from the player's own collection), so `artistOverride`/`rejection` semantics from CLAUDE.md are structurally inapplicable here rather than violated; `match.artistOverride` is checked in BeatmapRow (PlayerSections.js:123) but will never be true for a player-sourced song.
- **ui-glitch-parity (desktop/mobile)**: PlayerProfile.js/PlayerResults.js/PlayerSections.js are shared components (no separate mobile variant, unlike SongRow/SongCardMobile), and all widths in the files read use `flexWrap`/`minmax` responsive patterns with no fixed px widths that would force horizontal scroll at phone width; not exhaustively tested at a real phone viewport in this pass.

## Summary

Severity counts: high 4 (PLY-01, PLY-02, PLY-04, PLY-06), medium 5 (PLY-03, PLY-05, PLY-07, PLY-08, PLY-09), low 2 (PLY-10, PLY-11).

Top 3: (1) PLY-01 -- players with >100 most-played/favourite maps silently lose the true count with no truncation notice, verified live against peppy (469 -> 88 shown). (2) PLY-04/PLY-05 together -- mode/status changes on the player screen always refetch every open section from osu!, even when the data provably can't have changed, with no debounce, so this screen is the cheapest way in the app to burn through the shared osu! rate limit. (3) PLY-02 -- the player routes drop `isDemo` entirely, so a keyless deployment shows a misleading "no players found" or a raw 503 instead of the app's own setup guide.
