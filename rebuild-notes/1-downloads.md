# Audit: downloads

Traces the full download path: single/batch/ZIP click handlers in page.js, the browser-side mirror fetch in beatmapDownload.js, the server-side proxy fallback in /api/download, and the download buttons in StatsBar/PlayerSections/DownloadToast.
Focus: the 2026-09-23 Fast Origin Transfer incident (proxy streamed every .osz through a Vercel function) and whether the browser-first mirror fetch + capped proxy fallback actually closes that hole.
Findings below are tagged verified/traced/speculative per instructions; reproduction commands and outputs are inline.

## Dimensions with no findings

- **rendering-performance**: no distinct rendering-performance defect found beyond the memory pressure already captured under DL-06 (memory-resource-leaks); `DownloadToast.js`'s drag/physics animation loop (rAF-driven, `src/components/DownloadToast.js:81-120`) correctly cancels its own frame on unmount/dismiss and does not appear to leak.
- **ui-glitch-parity**: the single-download button's disabled/loading state is identical between desktop and mobile (`grep onDownloadSingle|isDownloading` on `src/components/SongRow.js:15-16,463,465,481` and `src/components/SongCardMobile.js:15-16,430,432,449` match line-for-line in shape), and `StatsBar.js`'s Download/ZIP buttons are the same shared component instance for both layouts (`src/app/page.js:953,1023` both wire the same `handleDownloadBatch`/`handleDownloadZipBatch`), so DL-05's missing re-entrancy guard is a shared bug, not a desktop/mobile divergence.

## Summary

14 findings total. Counts by severity: **critical: 2** (DL-01, DL-02) · **high: 5** (DL-03, DL-04, DL-05, DL-06, DL-12) · **medium: 2** (DL-09, DL-10) · **low: 5** (DL-07, DL-08, DL-11, DL-13, DL-14)

Top 3:
1. **DL-01** — `/api/download` is still exactly the unauthenticated, uncapped, byte-streaming function that caused the 10.24GB incident; the 5-per-batch budget the rebuild added only exists in the browser bundle, so anyone calling the route directly bypasses it entirely.
2. **DL-02** — verified live: the synthetic placeholder .osz comes back as HTTP 200 with a 1KB body, and `beatmapDownload.js` applies its "is this real" size check to mirror blobs but not to proxy blobs, so every layer above it (single/batch/ZIP, and the toasts in DL-12) reports a placeholder as a successful download with no way for the user to tell.
3. **DL-04/DL-03** — the proxy's own mirror walk is measurably worse than it needs to be: its first mirror (catboy.best) 403s the proxy's own User-Agent on every single call (verified), and its second and third steps (catboy, nerinyan) repeat mirrors the browser already tried and failed, burning most of the 24s serial budget before reaching the two mirrors that could actually be new information.
